# TaoPad 更新日志

## 1.0.9（2026-11-06）

**真机修复：行号栏/小地图墨夜白带（1.0.6 陶瓷渐变引入的读取失灵）**

- 现象：墨夜下行号栏（窗口左缘）与小地图列（窗口右缘，恰 72px）停在首主题白，
  截图像素取证两区颜色精确等于取色保底色 (248,249,250)，而行号字形已是墨夜
  关键字色 #7FB0CC——同函数内普通键查得到、Ant.Surface 查不到。
- 根因：Ant.Surface 在 1.0.6 陶瓷换装后被 ApplyCeramic 替换为 LinearGradientBrush，
  真机上应用级合并链对该渐变键的解析/精确类型匹配失灵，TryBrush 退回保底色。
- 修复三层：① TryColor 渐变识别放宽到 GradientBrush 基类（不再依赖精确类型）；
  ② 取色失败时直连 ThemeService.CurrentDictionary（Swap 刚合并的原字典）兜底；
  ③ 行号栏/小地图底色改走专属键 Ant.GutterBg（三象齐备、纯色、不经陶瓷换装）。
- 回归断言：R6 更新为 GutterBg 接线（且 Ant.Surface 保底色用法清零）；
  R8 兼容断言更新为基类匹配 + 直连字典双保险。

## v1.0.8（2026-11-06，真机修复：换肤链路加固）

- 真机缺陷（1.0.7）修复：用户真机截图显示换墨夜后标题栏/菜单/标签条/正文
  已随墨夜（1.0.7 主体修复生效），但行号栏、右侧小地图/滚动区、状态栏三处
  停在首主题水墨白。根因定性为换肤链路两处结构性隐患：① App.xaml 静态合并
  的水墨字典永远留在应用级合并链中，与运行时交换进来的主题字典叠加，同一
  主题键在链上存在多份，命中次序因 XAML 解析与运行时取值路径而异，首主题
  残留由此而来；② 主题直涂（ApplyThemeBrushes）与编辑器换肤回调
  （CodeEditor.OnThemeApplied）整段共用一个 try，任何一环异常都会让排在
  后面的大面拿不到新主题笔刷且被静默吞掉。
- 修复：Swap 摘除链上全部 Ant 主题字典（含静态水墨），任一时刻只保留一份；
  直涂与回调改为逐面隔离（窗底/状态栏/内容层/窗控、正文底色/弹层/行号栏/
  小地图与滚动条/重墨各自独立 try），失败面写入崩溃日志（数据根 crash.log）
  可追溯。
- 回归线：全测 200 项 0 失败（R8 陶瓷三键/R2 滚动条三接线/N3 复位先行等
  断言全部在位）；构建 0 错 0 警。
- 验收点：真机水墨→天青→墨夜来回切换，重点核对行号栏、右侧滚动区、
  状态栏三处是否随主题即时刷新；如有残留，将数据根下 crash.log 发回定位。

## v1.0.7（2026-11-06，真机修复：换肤作用域）

- 真机缺陷（1.0.6）修复：切换主题后卡片/编辑区/状态栏停留首主题色，
  用户所见为"墨夜换不回来"。根因：陶瓷渐变笔刷被写入应用级资源
  （Application.Current.Resources），主题字典交换（Swap）只移除/替换合并
  字典，应用级直写条目跨主题残留且遮蔽新主题字典同名键——Ant.Surface、
  Ant.EdBg、LayerFillColorDefaultBrush 三键自首主题应用后永远停留在
  首主题的陶瓷色，首主题之外换任何主题均失真。
- 修复方式：Swap 返回本次实际合并生效的主题字典，陶瓷渐变只写进该字典
  （TryGetValue→写回，作用域随字典交换消亡）；应用级不再有任何主题色
  直写。代码取色（TryColor 渐变主体帧）与大面直涂（ApplyThemeBrushes）
  经合并字典链照常命中，行为语义不变。
- 回归线：全测 R8 扩为"换装/作用域随字典/主体帧取色/异常退纯色/天青文案
  清零"，断言锁定渐变不入应用级、Swap 返回字典；主题三象循环
  水墨→天青→墨夜→水墨各键色值随象刷新。
- 全测 200 项 0 失败（131 主 + 69 扩展），类型检查 0 错 0 警。
